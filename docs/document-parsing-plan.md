# 文档解析与父子分块方案

## 状态与目标

本方案依据 2026-10-06 用户确认整理：各格式直接输出项目统一结构块，父块统一按结构切分，子块使用本地递归切法并继承父块元数据。扫描 PDF 继续复用现有 Vision OCR，不新增 OCR 引擎。

已接入所有格式的统一结构块，删除旧父块逐行分类分支，切块版本更新为 `structured-chunker-v7`。父块目标 2000 字符、硬上限 2500；子块目标 200 字符、硬上限 250，普通正文最多重叠 60 个完整句子字符。标题路径只存入块元数据，不拼入父块正文。OCR 不再使用 20 次调用预算，也不再设置项目 `max_tokens`；保留装饰图过滤、重复图片缓存、大小限制、超时与失败统计。供应商自身的能力上限仍存在，未完整结束的 OCR 响应明确失败。

真实验证已覆盖文字 PDF、扫描 PDF、混合 PDF、DOCX 的解析、数据库父子关系、1024 维向量与版本锁，以及 Markdown 图片的真实视觉识别。扫描表格 44 行、文字表格 80 行的唯一编号在父块和子块中各出现一次。自动回归中的 23 页 OCR 文本使用模型替身，截图渲染是真实的；没有把它当作 23 页真实模型验收。

目标：物理页码可靠关联到源内容；分页不强制结束 section；跨页段落和长表格在尺寸限制内切分；所有子块可回查父块；解析失败或模型输出截断不能静默冒充完整解析。

## 各格式解析入口

| 类型      | 当前解析方案                                                        | 来源定位                             |
| --------- | ------------------------------------------------------------------- | ------------------------------------ |
| 文字 PDF  | Docling 文档树，启用标题层级推断；图片原位 Vision 回填              | 物理页号与节点/单元格来源            |
| 扫描 PDF  | pdf-parse 每页截图 + 现有 Vision + remark/GFM AST                   | 截图页号绑定节点，模型不生成页码     |
| 混合 PDF  | 缺少可用文字的页 OCR，文字页 Docling；先排除 OCR 页的图片回填       | 按物理页恢复阅读顺序，避免同页重复   |
| DOCX      | Docling 原生标题、表格、列表、代码和图片                            | 不制造 Word 渲染页码，pageNumbers=[] |
| Markdown  | unified/remark-parse/remark-gfm；保留图片下载白名单、原位识别与缓存 | 原始 Markdown 行号，无物理页码       |
| TXT       | BOM/UTF-8/UTF-16/GB18030 解码、保守段落、保留缩进                   | 原始文本行号，不猜测 # 或编号标题    |
| CSV/Excel | 原生行/单元格；保留空行坐标，分工作表及区域输出表格                 | 工作表名与原始记录行号，不当作页码   |
| 图片      | 现有 Vision + AST，不添加伪页码章节                                 | 图片内结构节点，无 PDF 页码          |

Markdown AST 已接回内嵌图和可信外链处理，代码示例中的图片链接不执行下载。TXT 中无围栏的代码缺乏可靠类型证据，优先原样保留，不能保证自动识别全部标题和代码。

## 统一结构协议

沿用并扩展项目的 ParsedContentBlock，不要求所有解析器生成 DoclingDocument。所有解析器必须提供结构块，缺失时明确失败，删除旧的 Markdown 按行分类父块入口。

- 块基本信息：稳定 sourceId、kind、原始或序列化正文、标题 level、文档阅读顺序。
- 分页来源：pageNumbers 保留实际页号集合；pageStart/pageEnd 仅用于展示范围。物理页码从 1 开始，不等同于文档印刷页码。
- 文本来源：lineStart/lineEnd 对应原始文本行号。
- 表格来源：tableId、sheetName、表头行、数据行、每行/单元格的 sourceId 和页码或行号。
- 上下文信息：完整 `metadata.headingPath`；父块正文只保留实际内容，标题路径由检索和提示词从元数据读取。重复标题、表头、键列属于上下文副本，应与实际数据来源区分。

先绑定来源，再清洗和序列化；不要用处理后字符串首尾匹配来恢复页码。展示用整篇 Markdown 与切块输入分开生成，避免格式化移动内容破坏来源对应。

## 扫描 PDF 与混合 PDF

1. 按真实页号渲染截图，复用现有模型用途为 ocr 的调用。
2. 调整文档页识别提示词：按阅读顺序转写文字，保留标题标记、表格和代码，禁止添加摘要、虚构标题或 `PDF 第 N 页` 这类章节包装。
3. 每页原始 Markdown 用 AST 解析，给所有节点绑定截图页号，再汇集整篇节点；不使用现有 formatVisionDescriptions 添加的 `## PDF 第 N 页` 作为标题。
4. 全篇只维护一份标题层级状态，分页不重置路径。OCR 标题 level 是模型识别结果，不能宣称与原始字号层级完全一致。
5. 同一 section 内相邻页面的正文允许进入同一父块。段落是否真正跨页续接，依据末尾句子是否未结束、下一页首节点类型和前后上下文判断；有歧义时保留两个段落节点，仍允许同 section 合并。
6. 任一正文页失败，须记录页号并重试；仍失败时本次处理不能标记为完整成功。空白页须与识别失败区别处理。
7. 检查模型 finish_reason，length 或其他未完成输出不能直接入库。必要时按区域重新识别并去重；无法恢复时明确失败。取消项目 token 参数不代表供应商输出无限。

## 父块与标题上下文

- 遇到真实 heading 节点结束当前 section，按标题 level 维护祖先栈；支持跳级标题，不用数组下标假定层级连续。
- 同 section 内按完整结构节点和尺寸合并。页码变化不触发 flush；不同工作表或不同 tableId 不混成一张表。
- 父块正文只保留实际内容；完整标题路径只存入元数据，不占正文长度预算，也不把祖先标题所在页计入当前数据页码。
- pageNumbers 从本次父块实际内容片段的来源汇总；pageStart/pageEnd 取最小/最大值。若原始大节点跨页且缺少内部定位，只能提供节点页码范围，并明确来源精度。
- 正文、表格、代码采用各自的切分规则；长表格单独成为父块，避免混合正文影响表格子块识别。
- 父块目标 2000 字符、硬上限 2500；正文长度不包含元数据中的标题路径。单个表格或结构节点无法在上限内无损保存时明确失败。

## 跨页表格与长表格

### 续表识别

只有相邻页的表格同时满足同一章节/表格上下文、列结构兼容，以及表头一致或明确续表证据时，才归为同一个 tableId；没有足够证据就保留为独立表格，不凭列数相同强行合并。

重复表头只作为上下文保留一次，数据行保留各自页码；不删除与表头文字巧合相同的真实数据行。OCR 跨页断行目前不主动猜测重建，保留各页识别出的记录及来源；Docling 已合并的多页单元格保留其来源范围。

### 长表格切分

1. 从 AST 或原始单元格读表格结构，不用竖线字符串 split 猜列，正确处理转义竖线和单元格换行。
2. 预留表头后按完整数据行打包；每个父块、子块重复表头，保持表格结构可读。
3. 每个父块只汇总它包含的数据行页码。重复的表头不让后面的块都错误地引用第一页。
4. 单行超过上限时，按单元格内部语义拆分并重复行标识、列名；必要时改为带字段名的记录片段，不能直接切碎 Markdown 行。
5. 极宽表格使用逐列字段记录，重复源行 ID；不自动推断业务主键。完整列名同时保留在 tableRecords 元数据中。
6. 表格子块不做普通文本 overlap；重复表头/行标识承担上下文。每条原始数据有 sourceId，可核对无遗漏及非预期重复。

Docling 适配器现在导出表格行/单元格来源。普通 TableCell 自身没有 page_no：单页节点可精确定位到该页；RichTableCell 可利用引用子节点 provenance；跨页节点缺少单元格来源时保留整节点范围，标记 precision=block，不声称逐行精确。

## 子块、入库与检索

- 子块继续使用项目本地递归策略：完整块、段落、句子逐级拆分；代码按代码行并补围栏；最后才对无语义边界的超长内容按 Unicode 码点兜底。
- 子块目标 200 字符、硬上限 250；普通正文最多重叠 60 个完整句子字符，表格和代码不做普通文本 overlap。
- 子块通过 parentChunkId 关联父块，继承 parentTitle，并在子块 metadata 中保存 `headingPath`、pageNumbers、pageStart/pageEnd、sources、tableIds、tableRecords，pageScope=parent。子块页码明确代表父块上下文范围，不声称是子块自身的精确页码。
- 检索仍用子块召回、父块恢复正文；标题路径从父块 metadata 读取并单独放入重排与答案提示词，不拼接到父块正文。
- 父子块在同一事务内替换，旧任务不得覆盖新的 processVersion；切块版本更新后历史文档通过“重新处理”应用新方案。

## 验收数据与判定

| 场景                      | 验收要求                                                                    |
| ------------------------- | --------------------------------------------------------------------------- |
| 超过 20 页扫描 PDF        | 每个非空页均有识别结果；后续页不因项目调用预算跳过；实际请求不传 max_tokens |
| 密集扫描页/模型输出截断   | 能识别未完成响应并恢复或明确失败，不静默保存截断正文                        |
| 同段正文跨两页            | 可在同一 section 合并；父块来源包含两页；不产生人为分页标题                 |
| PDF 混合文字页与扫描页    | 两种页面均有正文，没有遗漏和重复转写                                        |
| 跨页续表、重复表头        | 同一 tableId 保留完整数据行，每个切片补表头，页码对应实际行                 |
| 两张列数相同的独立表      | 不因结构相似误合并                                                          |
| 单行/表头超过尺寸上限     | 保留行、列定位信息，不输出损坏表格，不丢正文                                |
| 多工作表 XLSX/XLS         | 工作表名和原始行号对应正确，页码为 null                                     |
| TXT 含 # 注释、编号和缩进 | 原文保留，不错误生成标题 section                                            |
| MD 围栏代码中含标题符号   | 作为 code 节点，围栏内 # 不进入标题栈                                       |
| 全部父子块                | 子块均有真实父块；标题路径、来源字段一致；重建源内容核对无遗漏              |

真实样本已通过解析、父子入库和向量化验收；检索仍使用既有子块召回、父块恢复入口，浏览器端验收留给 Gemini/CC。低质量扫描识别与标题层级取决于模型；跨页节点只有块级来源时保持范围标记，不伪造更细的页码。

## 本地验证命令

在仓库根目录运行：

```powershell
.\services\docling\docling.ps1 start -Offline
$env:DOCLING_INTEGRATION='1'
pnpm --filter @knowflow/api test
pnpm lint
pnpm typecheck
pnpm build
pnpm --filter @knowflow/api exec tsx src/scripts/document-parser-smoke.ts txt
pnpm --filter @knowflow/api exec tsx src/scripts/document-parser-smoke.ts pdf
pnpm --filter @knowflow/api exec tsx src/scripts/document-parser-smoke.ts docx
pnpm --filter @knowflow/api exec tsx src/scripts/docling-smoke.ts md
```

专项样本支持 `document-parser-smoke.ts pdf <PDF绝对路径> <费用表行数>`，文字表样本再加 `--native`。费用表用 `CODE001` 开始的编号核对数据完整性。脚本验证真实数据库、存储、向量模型和父子元数据，结束后只清理本次随机生成的记录；专项 JSON 报告写入 `output/docling/<样本名>-report.json`。

当前真实样本结果：

| 样本            | 页数 / 数据行  | 父块 / 子块 | 父块页码集合         |
| --------------- | -------------- | ----------- | -------------------- |
| 文字 PDF        | 1 页           | 1 / 1       | [1]                  |
| 文字跨页表格    | 2 页 / 80 行   | 4 / 9       | [1]、[1]、[1,2]、[2] |
| 扫描跨页表格    | 3 页 / 44 行   | 4 / 7       | [1]、[1,2]、[2]、[3] |
| 文字 + 扫描 PDF | 2 页           | 2 / 2       | [1]、[2]             |
| DOCX            | 不提供物理页码 | 2 / 2       | []、[]               |

扫描表格首个父块是独立一级标题；两个表格父块带完整标题路径。上述样本的子块关联、来源继承、1024 维向量和旧任务/重复任务跳过均已核对。历史文档不自动迁移，需要重新处理。
